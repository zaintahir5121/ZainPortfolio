1 What Is Experion

Experion is a drop-in AI agent within the AG ONE product series. It is delivered as a single JavaScript file hosted on Azure Blob Storage (CDN) and backed by a .NET 8 API. Any product in the AG ONE series — or any external .NET application — can embed Experion with a single <script> tag.

Experion combines two roles: an Activity-Mining Agent (passively watches user behaviour) and a Recommendation / Chatbot Agent (responds to requests, takes actions, surfaces proactive suggestions).

Integration Rule: Each product team works independently and integrates with Experion via its API only. No product team has direct access to Experion's database, JS SDK code, or internal services.

2 AG ONE Routing — How It Works

AG ONE acts as the central orchestrator. Every request — regardless of which product it originates from — is received by AG ONE, which then decides the path:

Path Triggered When What Happens LLM Used?
Generation User asks a question, wants an explanation, or circles a UI element RAG pipeline — KB retrieval → Azure OpenAI → answer + chips Yes
Action User requests an action (add to cart, checkout, apply coupon…) NLP routing → ActionMappings SQL lookup → queue → worker No
Chat Conversational follow-up tied to session history History loaded from Blob → Generation pipeline with context Yes

Per-Product Response Weights

Each product in the AG ONE series has its own configurable weights that control how Experion prioritises each response type for that product's context:

4 /process Pipeline — Step by Step

1
Embed Query The user's text is converted into a vector using Azure OpenAI Embeddings.
2
Semantic Cache Check Cosine search over the SemanticCache table. A HIT short-circuits the LLM and returns in <15 ms (vs 60–2000 ms for a full LLM call).
3
NLP Intent Router Hybrid score (embedding cosine + phrase Jaccard) against ActionMappings. Classifies the request as ACTION or GENERATION.
4a
Run Action (if ACTION) Dispatch an ActionJob to the queue. Background worker executes the action and calls the product's targetEndpoint. SignalR echoes result back to SDK.
4b
Run Generation / RAG (if GENERATION) Load conversation history from Blob → retrieve KB chunks → call Azure OpenAI GPT-4.1 → return answer + suggestion chips.
5
Persist Write two JSONL lines (user turn + assistant turn) to Blob. On cache miss, write answer back to SemanticCache. Always write an AuditLog row to SQL.

5 /track Pipeline — Activity Ingest

1
SDK Batches EventsEvents are collected client-side and posted every ~5 seconds, or immediately on page unload via sendBeacon.
2
Append to BlobEach event is appended as a JSONL line to activity/{tenant}/{userId}/{yyyy-MM-dd}.jsonl.
3
Update UserProfileCounters in the SQL UserProfile table are updated.
4
RecommendationEngineReads recent activity blob → applies trigger rules (e.g. ≥5 events in 30 s, cooldown not active) → LLM drafts a nudge → SignalR pushes it to the SDK.
Performance note: Activity ingest is fully async (fire-and-forget). It never blocks the chat or action path.
