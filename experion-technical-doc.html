1 System Overview & Architecture

Experion is a drop-in AI agent for the AG ONE product series. It is delivered as a single JavaScript SDK (hosted on Azure Blob CDN) backed by a .NET 8 API. The core design principle is full product team independence — each product integrates via a one-time config registration and a single script tag. No product team ever touches Experion's internals.

2 Intent Resolver — Deep Dive

The Intent Resolver is the brain of the /process pipeline. It receives the embedded query vector and decides whether the request is an ACTION, a GENERATION, or a CHAT. The decision happens before any LLM call — ensuring actions never waste tokens.

2.2 Scoring Algorithm

Hybrid Score Formula: finalScore = (cosineWeight × cosineSimilarity) + (jaccardWeight × jaccardScore)
Default: cosineWeight = 0.7, jaccardWeight = 0.3. Per-product weights multiply the final score.
Score ComponentWhat It MeasuresRangeDefault Weight
Cosine SimilaritySemantic closeness between query vector and action embedding0.0 – 1.070%
Phrase JaccardWord overlap between query and action's example phrases0.0 – 1.030%
Per-Product Action WeightTenant-level multiplier — biases toward or away from action classification0.0 – 2.01.0 (neutral)

Stored in TenantConfig. The Experion team sets these during onboarding based on what each product primarily does:

2.4 Code Reference — IntentResolver.cs

public class IntentResolver { private const double ACTION_THRESHOLD = 0.72; private const double COSINE_WEIGHT = 0.70; private const double JACCARD_WEIGHT = 0.30; public IntentResult Resolve( float[] queryVector, string queryText, List<ActionMapping> mappings, TenantConfig tenant, bool hasConversationHistory) { // CHAT bias — if user is in an active conversation, lean toward CHAT if (hasConversationHistory && IsFollowUp(queryText)) return new IntentResult { Type = IntentType.Chat }; ActionMapping bestMatch = null; double bestScore = 0; foreach (var mapping in mappings.Where(m => m.Enabled)) { double cosine = CosineSimilarity(queryVector, mapping.Embedding); double jaccard = JaccardScore(queryText, mapping.Phrases); double hybrid = (COSINE_WEIGHT * cosine) + (JACCARD_WEIGHT * jaccard); double final = hybrid * tenant.ActionWeight; // per-product bias if (final > bestScore) { bestScore = final; bestMatch = mapping; } } if (bestScore >= ACTION_THRESHOLD && bestMatch != null) return new IntentResult { Type = IntentType.Action, Mapping = bestMatch }; return new IntentResult { Type = IntentType.Generation }; } }
Note for developers: ActionMapping.Embedding is pre-computed when the row is inserted. Never re-embed at runtime — it would defeat the purpose of the fast action path.

3.1 Action Path — Detail

1
Match ActionMappingIntent Resolver identifies the best matching ActionMapping row (actionKey + targetEndpoint).
2
Dispatch ActionJobAn ActionJob message is pushed to the Service Bus queue: { tenantId, userId, actionKey, targetEndpoint, sessionId }
3
ActionWorker ExecutesBackground worker dequeues the job and calls POST {targetEndpoint} on the product's own API with the user context.
4
Product Executes InternallyThe product handles the action in its own codebase (e.g. adds to cart, applies coupon). Experion does not know the internal logic.
5
SignalR ACKActionWorker pushes a confirmation message to the SDK via SignalR hub. SDK shows a toast or updates the UI.
// ActionJob model public record ActionJob( string TenantId, string UserId, string SessionId, string ActionKey, string TargetEndpoint // e.g. "https://learn.agone.com/api/experion/action/add_to_cart" ); // ActionWorker — executes the action by calling the product's endpoint public class ActionWorker : BackgroundService { protected override async Task ExecuteAsync(CancellationToken ct) { await foreach (var job in _queue.ReadAllAsync(ct)) { var payload = new { job.UserId, job.SessionId, job.ActionKey }; var response = await _http.PostAsJsonAsync(job.TargetEndpoint, payload, ct); await _signalR.SendToUserAsync(job.UserId, "ActionResult", new { job.ActionKey, Success = response.IsSuccessStatusCode() }); } } }

3.2 Generation Path (RAG) — Detail

// ExperionService.cs — Generation pipeline public async Task<ProcessResult> RunGenerationAsync(ProcessRequest req, float[] queryVec) { // 1. Load conversation history from Blob var history = await _blob.LoadConversationAsync(req.TenantId, req.UserId); // 2. Retrieve relevant KB chunks from Azure AI Search var chunks = await _search.RetrieveAsync(req.TenantId, queryVec, topK: 5); // 3. Build prompt (system = KB chunks, history = prior turns) var messages = BuildMessages(history, chunks, req.Text, req.CapturedText); // 4. Call Azure OpenAI var answer = await _openai.ChatAsync(messages); // 5. Persist turns + update SemanticCache await _blob.AppendTurnsAsync(req.TenantId, req.UserId, req.Text, answer.Text); await _cache.WriteAsync(queryVec, answer.Text); return new ProcessResult { Answer = answer.Text, Chips = answer.Chips }; }

3.3 Chat Path — Detail

The Chat path is identical to Generation but loads the full session history and optionally fetches a live product context snapshot via GET /context on the product's API. This allows Experion to give answers that are aware of what the user is currently doing in the product (e.g. current cart contents, active form, current page).

// Optional context call to the product's /context endpoint ProductContext? ctx = null; if (tenant.ContextEndpoint != null) ctx = await _http.GetFromJsonAsync<ProductContext>( $"{tenant.ContextEndpoint}?userId={req.UserId}&sessionId={req.SessionId}" );

3.4 Product Callback — How Experion Calls Back to Products

Key architectural point: Experion is not a closed black box. For actions, Experion calls out to the product's registered targetEndpoint. For chat context enrichment, it calls the product's /context endpoint. Products register these endpoints once — Experion handles the rest.

10 Performance & Cost Design Decisions

DecisionWhyImpact
Semantic Cache checked firstSame/similar questions asked repeatedly by different users — no reason to call LLM each timeCache HIT: <15 ms. Typical LLM call: 800–2000 ms. 30–60% of questions expected to be cache hits at scale
Action path calls no LLMAn action like "add to cart" needs routing logic, not text generationAction latency: 10–50 ms vs 800+ ms. Zero token cost.
Activity ingest is asyncTracking should never make the user waitZero impact on chat/action response time regardless of event volume
Conversation history in BlobSQL is expensive at scale for append-heavy long textSQL stays small and fast. Blob costs ≈ $0.002/GB. History scales without SQL growth.
ActionMappings embeddings pre-computedIf we re-embed at query time, we waste 30–80 ms on every request just to compareIntent scoring is a pure in-memory cosine comparison — effectively 0 ms
Per-product weights in config not codeTuning product bias should not require a deploymentAdjust weights via SQL update, live within minutes
